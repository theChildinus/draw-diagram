# 个人 Draw.io 绘图规范

本文件定义跨图型的硬性规则。新建图默认采用 `default-visual-style.json` 中的白底、低饱和浅色、圆角节点和简洁正交连线；布局仍根据关系语义决定。三个案例只能提供结构启发，不能覆盖本文件或默认视觉规范。

## 1. 内容和证据

- 一张图只回答一个主要问题。节点、关系、边界和阅读方向都服务于这个问题。
- 绘制现状图前，用当前代码、配置、接口或权威资料确认事实。
- 区分已确认事实、用户明确给定的设计、合理假设和证据缺口。
- 把功能职责归给代码或配置中实际执行、管理该功能的组件。区分运行进程、管理组件、工作目录和能力配置；不要把共享目录、Skill 集合或提示词画成运行时管理主体。
- 无法确认但不影响主结构的内容放在交付说明中；会改变关键链路时先询问用户。
- 不为了画面整齐删除真实次要路径，也不为了显得完整添加没有证据的关系。
- 信息量超过最终载体承受范围时，拆成总览和细节图，不缩小字号硬塞。

## 2. 修改已有图

- 默认延续原图有效的配色、字体、形状、间距和整体布局。
- 只修改本次需求涉及的对象和关系，保留无关内容与用户改动。
- 用户明确要求改成默认风格、要求重绘，或现有布局已经妨碍表达时，才重做整体视觉体系。
- 修改前后都校验 `.drawio`。文件移动、重命名和非视觉元数据调整不导出预览；局部视觉变化在合并修改后只回看一次受影响区域；新建、全局布局或多区域变化才检查整图。

## 3. 布局

- 先确定阅读方向，再安排节点。流程和架构通常从上到下或从左到右；不要混用多个主方向。
- 同层、同阶段或同类型对象保持对齐、尺寸和间距一致。
- 容器表示真实边界，不作为装饰。子节点使用真正的父子关系，不只是叠放在大矩形上。
- 在当前图或当前页内，主链比支撑关系、状态回传和说明更醒目。复杂图中的连线语义尽量不超过三类；多页文件不要把一页的主链判定带到另一页。
- 新图默认以浅蓝色表示核心业务服务；调度、编排和控制面使用浅紫色；存储使用浅青绿色；消息、事件和异步任务使用浅橙黄色；外部系统使用浅灰色；监控、日志和告警使用浅青蓝色。精确值以 `default-visual-style.json` 为准，图中没有对应角色时不使用该颜色。
- 填充色只表示稳定的功能类别。同一角色使用同一颜色；一个节点只有一个主要角色，不用多色叠加表示类别、团队和状态。
- 形状表示资源或元素类型：服务使用矩形或圆角矩形，数据存储使用圆柱体，判断使用菱形，用户或客户端使用对应通用形状并保留文字标签。
- 外框、泳道和分区表示真实归属或边界，例如系统、团队、环境、集群、云账号和命名空间；不要用节点填充色重复表示归属。
- 外层分区和大型背景容器必须与内部卡片分开设置圆角。空白、不可连接的背景容器（`pointerEvents=0` 或 `container=1`）在宽、高都不小于 `300 px` 时，若使用 `rounded=1`，必须显式设置 `arcSize<=4`，默认使用 `arcSize=4`；也可以使用 `rounded=0`。普通卡片可以使用 `10–14` 的圆角，但不得把该数值直接复用到大型容器，否则会因比例缩放形成椭圆或胶囊外观。
- 线型表示关系类型：实线表示同步调用，虚线表示异步消息，点线表示监控或状态回传。线条颜色只区分普通、辅助、异常和需要强调的可观测性关系，不跟随起点或终点的节点类别。精确值见第 7 节和 `default-visual-style.json`。
- 运行状态使用带文字的角标或边框表达，不覆盖节点的功能类别。正常、警告、故障分别使用绿、黄、红；待建设和已废弃必须带文字，并辅以虚线或不同边框。不能只靠颜色表达状态。
- 风险、故障和废弃路径优先使用红色边框或带文字角标，不大面积铺红；只有节点本身代表异常结果或错误终点时才使用浅红色填充。
- 需要突出当前焦点时，使用较粗边框、加粗名称或一个明确的焦点角标，不占用消息、风险等类别色。
- 默认采用“功能类别模式”。如果图的主要问题是健康状态或运行状态，改用“状态模式”：节点主体保持中性或弱化类别色，把绿、黄、红留给带文字的状态角标或边框；可能被误认为警告时，不使用橙黄色消息填充。
- 填充使用低饱和浅色，描边使用同色系较深颜色，正文统一使用 `#0F172A`。画布保持纯白；默认不使用阴影、渐变、纹理、手绘效果和装饰性图标。
- 一张图通常不超过五至七个语义色，包括状态色。不要为了丰富画面把所有颜色都用上，也不要给每个微服务分配一种颜色。
- 颜色不能成为唯一的信息载体。去掉颜色后，仍应能通过形状、标签、边界、线型和角标读懂主要类别、关系和状态。
- 需要图例时，直接展示对应的颜色、形状、边框或线型，并在样例中写明功能；不要只用“蓝色实线”“灰色虚线”等颜色名称解释图例。
- 外部参与者、第三方系统、文件和数据存储放在边界清楚的位置。
- 多条关系汇聚并跨越多个区域时，优先引入真实存在的网关、代理、总线或注册中心；不虚构中转节点。
- 留白用于分组和阅读，不用大面积空白制造“高级感”，也不强行把卡片拉到等高。

## 4. 形状和图标

- 默认使用矩形、圆角矩形、菱形、圆柱体、泳道和容器等通用形状。
- 普通模块和重点节点默认使用统一圆角矩形。节点文字尽量保持一行，节点宽高以 `160 × 60` 为视觉基线，再按内容和最终展示尺寸扩展。
- 决策使用菱形，数据存储使用圆柱体；同类对象保持同一形状语义。
- 只有用户明确指定厂商或领域视觉体系时才使用对应内置图标库。
- AWS、Azure、Google Cloud、Kubernetes 等官方图标保留官方原色和比例，不重染、不拉伸、不旋转；团队语义放在容器、边框、分区、标签和连线上。
- 不能确认精确图标时，使用带清楚名称的通用形状，并在交付说明中写明回退。
- 不用看起来相似但语义不同的图标冒充。

## 5. 字体和文字

- 图中文字按以下顺序处理：事实准确、沿用正式名称、受众能理解、表达简短、行文顺畅。不能为了好懂改错正式名称，也不能为了简短省略关键条件。
- 新建纯英文图默认使用 `Helvetica`；包含中文时默认使用 `PingFang SC`。全图只使用一个字体族。修改已有图时优先保留其可用字体。
- 普通节点和关系标签默认 `12 pt`，区域标题或重点节点默认 `14 pt`；重点节点可以加粗，普通节点保持常规字重。
- 字体层级最多四级：图标题、区域或阶段标题、对象名称、说明与连线标签。
- 同级文字的字号和字重一致。对象名称可以加粗，职责说明使用常规字重。
- 泳道、容器和分区表头默认左对齐；普通模块、数据存储、外部系统和图例内容默认居中。用户只说“框体文字”时，先区分表头、模块内容和独立说明，只修改目标类型。
- 图标题写清对象和视角。现状、目标、计划或假设会影响理解时，在标题、角标或图例中明确标出。标题尽量单行。
- 节点只保留名称和当前图需要的一项主要职责，命令、文件、状态和动作优先放在关系标签或细节图中。
- 按最终展示尺寸检查可读性。文字拥挤时依次精简、换行、扩大图形、调整布局；不要缩小字号勉强容纳。
- 普通节点只有名称和一句说明时，写入图形自身的 `value`；不得用同级独立文本框覆盖空白节点。
- 只在需要独立定位、不同样式、复杂排版，或内置标签确实错位时使用独立文本框；此时文本框必须是所属图形的子节点。
- UML 类成员行和 Draw.io 表格单元格等由 `stackLayout`/`tableLayout` 管理的结构化行不属于叠加文本框；它们按布局容器规则验收。

### 5.1 名称和术语

- 名称优先采用当前代码、配置、接口、正式文档或用户材料中的写法。旧图中的名称只作为线索，不能覆盖更新的证据。
- 同一概念有多种叫法、受众可能不熟悉术语，或名称差异会改变语义时，先整理“来源名称、图中名称、含义”；简单图不额外维护术语表。
- 同一个对象、动作和状态全图只使用一个名称。不要为了避免重复轮换近义词，也不要把同一组件写成多个简称。
- 函数名、接口、字段、命令和文件名保持原样。解释文字使用受众熟悉的语言，不随意翻译或改写代码标识符。
- 受众可能不熟悉的专业词或缩写，在首次出现处、图例或图下说明中写出常见中文含义，例如“消息队列（MQ）”。面向熟悉该术语的专业受众时不重复解释，也不要为了排版新造简称。
- 材料没有给出名称时，使用能直接说明对象或动作的常见词。不要拼接出看似专业、实际没有明确含义的新词。

### 5.2 节点和连线文案

- 节点标题写产品、组件、资源、参与者或业务对象的准确名称。职责说明用一个具体动词写清它处理什么，例如“校验订单并扣减库存”，不要写“订单智能协同”。
- 连线标签写清动作或传递内容，例如“提交订单”“返回库存状态”或 `POST /orders`。不要只写“数据流转”“能力输出”“结果回传”；必须说明传的是什么数据、输出什么能力或返回什么结果。
- 判断分支写可核对的条件或结果。异常路径写明失败、拒绝、超时或降级的原因，不只写“异常处理”。
- 状态标签写实际状态或可测结果，例如“等待审批”“重试 3 次后失败”。不能确认次数、时限或范围时，不自行补充数值。
- 标签应简短，但准确性优先。放不下时删除次要说明、扩大节点、调整布局或拆图，不把明确含义压成生造词和晦涩缩写。
- 一句话只表达一个主要意思。节点说明过长时拆成两行或移到细节图，不用堆叠名词和连续修饰语压缩句子。优先写“调用支付接口”“更新订单状态”，不写“支付接口调用能力”“订单状态更新处理”。

### 5.3 准确、自然、克制的表达

- `实时`、`自动`、`智能`、`统一`、`全量`、`高可用`、`安全`、`零侵入`、`无损`、`精准`等能力、范围或质量描述，只有当前材料能够证明时才使用；否则改写为实际机制或删除。数量、时间、重试次数和适用范围保持来源原值。
- 删除宣传语、口号、夸张意义和无信息量的形容词。“赋能”“抓手”“闭环”“全域”“一体化”等词如果是正式名称或材料明确定义的概念，可以保留；否则不能用它们代替具体动作。
- 不使用“业内认为”“专家指出”“普遍来看”等模糊归因。需要表达判断时，写明来源；没有来源时标为假设或移到交付说明。
- 现状、目标、计划、假设和待确认内容使用带文字的标题、角标、边框或图例区分。当前图不需要表达这些状态时，移到交付说明，不为完整感全部塞进图中。
- 不为形式完整强凑三项、排比或“不是……而是……”句式。图中只保留回答当前问题所需的内容。
- 不写“这里展示了”“希望这能帮助理解”等聊天式说明。标题和注释直接说明对象、范围或结论。
- 自然表达不等于随意口语。工程图仍应简洁、准确，不加入与信息无关的情绪、幽默或个人态度。

## 6. 独立文本框和可点击边界

独立文本框容易吞掉外框的鼠标命中区域。必须同时满足：

- 按渲染后的文字内容收紧宽高，不充当布局容器，不近似复制外框尺寸。
- 单行文本框的目标宽度为文字宽度加 `16–24 px` 横向留白；无法测量时不超过外框宽度的 `80%`。
- 多行文本框可以超过 `80%`，但仍须保留连续点击带。
- 文本框设置 `connectable=0`，连接线只连接外框。
- 文本框不能覆盖外框边线、端口或箭头。

外框几何为 `(x, y, width, height)` 时：

~~~text
safeX = max(12 px, min(24 px, width × 8%))
safeY = max(6 px, min(12 px, height × 12%))

text.x >= shape.x + safeX
text.x + text.width <= shape.x + shape.width - safeX
text.y >= shape.y + safeY
text.y + text.height <= shape.y + shape.height - safeY
~~~

子文本框使用相对坐标时，以父图形的 `(0, 0)` 为原点应用同一公式。放不下时使用内置标签、扩大外框或调整布局，不降低安全距离。

静态校验器无法确认真实点击行为，且独立文本框覆盖范围接近安全边界时，才在 Draw.io `100%` 缩放下分别点击外框四边；四次都应一次选中外框。

## 7. 连线和箭头

- 边的 `source` 和 `target` 必须指向真实图形外框，不能指向标题、说明、边标签或独立文本框。
- 新图默认使用 `#334155`、`1.5 pt` 正交线、圆角折线和实心经典箭头。只有完全对齐、无需避障且直线更清楚时才使用直线。
- 先移动或对齐节点和端口，再添加折点。保持折点少而清楚，优先从节点中点沿水平或垂直方向进出。
- 同一种关系使用一致的线型、颜色和箭头。视觉线型只使用实线、虚线和点线；颜色和粗细每种只表达一个稳定含义。图中出现三类以上关系语义时增加简短图例。

### 7.1 线宽作用域和主链判定

线宽和“主链路”的判定只在一张图内生效；一个多页 `.drawio` 文件按单页分别判断。不要因为另一张图、另一页或同一组件在其他图中的角色，就复制 `2 pt` 或 `1.5 pt` 的选择。

按以下顺序判定当前图/页的核心主链：

1. 先根据图的标题、目的和阅读方向确定它要回答的主要问题。
2. 列出边的端点、动作和方向，标出不经过该边就无法读完主要问题的核心链路。
3. 只有属于这条核心链路的边使用 `2 pt`；普通同步、辅助依赖、状态回传、监控和异常路径默认使用 `1.5 pt`。
4. 当前图确实需要比较两条或多条同等重要的核心路径时，可以同时标为主链；并行准备、失败分支、回传和说明不能仅因靠近主链就加粗。
5. 主链边仍保留真实关系的实线、虚线或点线；因此主链上的异步消息可以是 `2 pt` 的虚线，但不能改成同步实线。

使用以下关系样式；“保留关系线型”表示异常、辅助或主链仍按实际关系选择同步实线、异步虚线或状态点线：

| 关系 | 颜色 | 线型 | 宽度 |
|---|---|---|---|
| 普通同步调用 | `#334155` | 实线 | `1.5 pt` |
| 主链路 | `#334155` | 保留关系线型 | `2 pt` |
| 异步消息、队列投递 | `#334155` | 虚线 `6 4` | `1.5 pt` |
| 状态回传、监控采集 | `#64748B` | 点线 `1 4` | `1.5 pt` |
| 次要依赖、辅助链路 | `#64748B` | 保留同步实线或异步虚线 | `1–1.5 pt` |
| 异常、失败、超时路径 | `#DC2626` | 保留同步实线或异步虚线，并带文字标签 | `1.5 pt` |
| 需要强调的可观测性链路 | `#0E7490` | 点线 `1 4` | `1.5 pt` |

- 不根据起点或终点的服务、控制面、存储等节点颜色给连线染色。白底上的必要关系线对比度至少为 `3:1`；不要用对比度不足的 `#94A3B8` 绘制必须辨认的关系。
- 判断分支从菱形对应尖角沿分支方向直出，并标出条件。
- 箭头垂直进入目标外框的直线段，避开圆角、边角和圆柱弧线转折处。
- 正交箭头的最后一段至少 `24 px`，末端 `24 px` 内没有折点；起点离开外框后至少保留 `16 px` 直线。
- 相邻折点形成的中间段通常不短于 `16 px`。不要用 S 形、台阶形或短钩补偿错位。
- 标签放在最长且稳定的中间线段，不放在折点、交叉点、端口或箭头前最后 `32 px`。
- 连接线不穿过节点或文字；容器边框、图形轮廓和其他线不能遮住箭头及末段。
- 多条线进入同一节点时分配不同落点，相邻落点通常至少间隔 `12 px`。

## 8. 文件和编辑性

- `.drawio` 是唯一事实源。Mermaid 只是临时输入，SVG、PNG、PDF 是导出物。
- 所有 `mxCell` ID 唯一；边必须包含 `source`、`target` 和相对 `mxGeometry`。
- XML 属性中的特殊字符必须转义。不要在生成的 Draw.io XML 中写 XML 注释。
- 容器内子节点使用相对坐标；跨容器边放在公共层，避免被父容器裁切。
- 自动布局前保留可恢复的原文件；布局结果仍需重新校验文本框、端口、分组和连线。
- 不因导出文件嵌入了 XML 而删除 `.drawio`。

## 9. 验收清单

### 事实

- [ ] 节点、边界、关系、方向和标签与当前证据一致。
- [ ] 功能职责归属于实际执行或管理该功能的组件，工作目录和能力配置没有被画成运行时管理主体。
- [ ] 设计、假设和证据缺口没有被伪装成已确认现状。
- [ ] 主问题、阅读入口和主链清楚。

### 结构

- [ ] XML 可解析，ID 唯一，边的端点都存在。
- [ ] 容器、子节点和跨容器边的父子关系正确。
- [ ] 独立文本框为 `connectable=0`，且通过 `safeX`、`safeY` 检查。
- [ ] 连线没有连接到文本对象。

### 文字

- [ ] 图中的名称来自当前材料或用户定义；没有生造术语、缩写、组件职责或概括性口号。
- [ ] 同一个对象、动作和状态使用同一个名称；代码标识符保持原样，受众不熟悉的专业词或缩写已在首次出现处、图例或图下说明中解释。
- [ ] 标题说明对象、范围和必要的状态；节点、连线、判断分支和状态标签写清当前问题需要的动作、对象、条件、传递内容或结果。
- [ ] 能力、范围、质量、数量和时间描述有当前材料依据；现状、目标、计划、假设和待确认内容没有混写。
- [ ] 精简后仍然准确、易懂；没有宣传语、模糊归因、聊天套话、生造词、晦涩缩写或名词堆叠。

### 视觉

- [ ] 全图字体族一致，层级不超过四级，同级样式一致。
- [ ] 分区表头与普通模块按各自规则对齐，没有因批量修改混用对齐方式。
- [ ] 新图默认使用白底、低饱和浅色填充、同色系较深描边、统一圆角节点、深灰色细正交连线；没有阴影、渐变、纹理或无意义装饰。
- [ ] 服务、控制面、存储、消息、外部系统、参与者、可观测性和风险色只在对应语义存在时使用；没有为了凑颜色而增加角色色。
- [ ] 填充色、形状、边界、线型、状态角标和焦点强调分别承担一种信息维度，没有让颜色同时表示类别、归属和状态。
- [ ] 状态模式已经把绿、黄、红留给带文字的状态角标或边框；消息色不会被误认为警告。
- [ ] 风险、故障和废弃路径没有大面积铺红，除非节点本身就是异常结果或错误终点。
- [ ] 去掉颜色后仍能通过形状、标签、边界、线型和角标读懂主要语义。
- [ ] 图例用视觉样例直接说明功能语义，一张图通常没有超过五至七个语义色。
- [ ] 主链、辅助链、状态回传和异常路径已在当前图/页内按语义区分；`2 pt` 没有因为跨图复用组件而滥用。
- [ ] 最终显示尺寸没有异常换行、裁切、遮挡、字体替换或过小文字。
- [ ] 节点和容器对齐，间距稳定，空白与内容量匹配。
- [ ] 外层分区和大型背景容器没有沿用卡片高圆角；大型背景容器使用 `rounded=0` 或显式 `arcSize<=4`。
- [ ] 不选择连线也能追踪起点、路径、方向和终点。
- [ ] 箭头末段、标签、折点和交叉点符合约束。

### 交付

- [ ] `.drawio` 可编辑并保持为事实源。
- [ ] 只生成用户要求、目标文档需要或临时检查需要的导出物。
- [ ] 已按视觉风险选择静态校验、局部预览或整图预览；无视觉变化时没有调用图片查看能力。
- [ ] 只有必要时才打开 Draw.io 图形界面。
