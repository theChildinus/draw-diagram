# 个人 Draw.io 绘图规范

本文件定义跨图型的硬性规则。布局、画布、配色、字号和线型根据当前场景决定；三个案例只能提供结构启发，不能覆盖本文件。

## 1. 内容和证据

- 一张图只回答一个主要问题。节点、关系、边界和阅读方向都服务于这个问题。
- 绘制现状图前，用当前代码、配置、接口或权威资料确认事实。
- 区分已确认事实、用户明确给定的设计、合理假设和证据缺口。
- 把功能职责归给代码或配置中实际执行、管理该功能的组件。区分运行进程、管理组件、工作目录和能力配置；不要把共享目录、Skill 集合或提示词画成运行时管理主体。
- 无法确认但不影响主结构的内容放在交付说明中；会改变关键链路时先询问用户。
- 不为了画面整齐删除真实次要路径，也不为了显得完整添加没有证据的关系。
- 信息量超过最终载体承受范围时，拆成总览和细节图，不缩小字号硬塞。

## 2. 修改已有图

- 默认延续原图有效的配色、字体、形状、间距和整体布局。
- 只修改本次需求涉及的对象和关系，保留无关内容与用户改动。
- 用户明确要求重绘，或现有布局已经妨碍表达时，才重做整体视觉体系。
- 修改前后都校验 `.drawio`。文件移动、重命名和非视觉元数据调整不导出预览；局部视觉变化在合并修改后只回看一次受影响区域；新建、全局布局或多区域变化才检查整图。

## 3. 布局

- 先确定阅读方向，再安排节点。流程和架构通常从上到下或从左到右；不要混用多个主方向。
- 同层、同阶段或同类型对象保持对齐、尺寸和间距一致。
- 容器表示真实边界，不作为装饰。子节点使用真正的父子关系，不只是叠放在大矩形上。
- 主链比支撑关系、状态回传和说明更醒目。复杂图中的连线语义尽量不超过三类。
- 默认使用一个强调色表达主链，使用中性色表达辅助关系和普通模块。颜色用于区分关系语义，不为每类组件单独分配颜色。
- 需要图例时，直接展示对应的颜色、边框或线型，并在样例框内写明功能；不要只用“蓝色实线”“灰色虚线”等颜色名称解释图例。
- 外部参与者、第三方系统、文件和数据存储放在边界清楚的位置。
- 多条关系汇聚并跨越多个区域时，优先引入真实存在的网关、代理、总线或注册中心；不虚构中转节点。
- 留白用于分组和阅读，不用大面积空白制造“高级感”，也不强行把卡片拉到等高。

## 4. 形状和图标

- 默认使用矩形、圆角矩形、菱形、圆柱体、泳道和容器等通用形状。
- 决策使用菱形，数据存储使用圆柱体；同类对象保持同一形状语义。
- 只有用户明确指定厂商或领域视觉体系时才使用对应内置图标库。
- 不能确认精确图标时，使用带清楚名称的通用形状，并在交付说明中写明回退。
- 不用看起来相似但语义不同的图标冒充。

## 5. 字体和文字

- 新建中文图优先使用 macOS 可用的中文系统字体；全图只使用一个字体族。修改已有图时优先保留其可用字体。
- 字体层级最多四级：图标题、区域或阶段标题、对象名称、说明与连线标签。
- 同级文字的字号和字重一致。对象名称可以加粗，职责说明使用常规字重。
- 泳道、容器和分区表头默认左对齐；普通模块、数据存储、外部系统和图例内容默认居中。用户只说“框体文字”时，先区分表头、模块内容和独立说明，只修改目标类型。
- 标题尽量单行。节点只保留名称和当前图需要的一句职责，命令、文件、状态和动作优先放在关系标签或细节图中。
- 按最终展示尺寸检查可读性。文字拥挤时依次精简、换行、扩大图形、调整布局；不要缩小字号勉强容纳。
- 单一居中名称优先写入图形自身的 `value`，不要叠加近似同尺寸的文字框。
- 只在需要独立定位、不同样式、复杂排版，或内置标签确实错位时使用独立文本框。
- UML 类成员行和 Draw.io 表格单元格等由 `stackLayout`/`tableLayout` 管理的结构化行不属于叠加文本框；它们按布局容器规则验收。

## 6. 独立文本框和可点击边界

独立文本框容易吞掉外框的鼠标命中区域。必须同时满足：

- 按渲染后的文字内容收紧宽高，不充当布局容器，不近似复制外框尺寸。
- 单行文本框的目标宽度为文字宽度加 `16–24 px` 横向留白；无法测量时不超过外框宽度的 `80%`。
- 多行文本框可以超过 `80%`，但仍须保留连续点击带。
- 文本框设置 `connectable=0`，连接线只连接外框。
- 文本框不能覆盖外框边线、端口或箭头。

外框几何为 `(x, y, width, height)` 时：

~~~text
safeX = max(12 px, min(24 px, width × 8%))
safeY = max(6 px, min(12 px, height × 12%))

text.x >= shape.x + safeX
text.x + text.width <= shape.x + shape.width - safeX
text.y >= shape.y + safeY
text.y + text.height <= shape.y + shape.height - safeY
~~~

子文本框使用相对坐标时，以父图形的 `(0, 0)` 为原点应用同一公式。放不下时使用内置标签、扩大外框或调整布局，不降低安全距离。

静态校验器无法确认真实点击行为，且独立文本框覆盖范围接近安全边界时，才在 Draw.io `100%` 缩放下分别点击外框四边；四次都应一次选中外框。

## 7. 连线和箭头

- 边的 `source` 和 `target` 必须指向真实图形外框，不能指向标题、说明、边标签或独立文本框。
- 优先直线；需要避障时再用正交线。先移动或对齐节点和端口，再添加折点。
- 同一种关系使用一致的线型、颜色和箭头。虚线、颜色和粗细每种只表达一个稳定含义；混用时增加简短图例。
- 判断分支从菱形对应尖角沿分支方向直出，并标出条件。
- 箭头垂直进入目标外框的直线段，避开圆角、边角和圆柱弧线转折处。
- 正交箭头的最后一段至少 `24 px`，末端 `24 px` 内没有折点；起点离开外框后至少保留 `16 px` 直线。
- 相邻折点形成的中间段通常不短于 `16 px`。不要用 S 形、台阶形或短钩补偿错位。
- 标签放在最长且稳定的中间线段，不放在折点、交叉点、端口或箭头前最后 `32 px`。
- 连接线不穿过节点或文字；容器边框、图形轮廓和其他线不能遮住箭头及末段。
- 多条线进入同一节点时分配不同落点，相邻落点通常至少间隔 `12 px`。

## 8. 文件和编辑性

- `.drawio` 是唯一事实源。Mermaid 只是临时输入，SVG、PNG、PDF 是导出物。
- 所有 `mxCell` ID 唯一；边必须包含 `source`、`target` 和相对 `mxGeometry`。
- XML 属性中的特殊字符必须转义。不要在生成的 Draw.io XML 中写 XML 注释。
- 容器内子节点使用相对坐标；跨容器边放在公共层，避免被父容器裁切。
- 自动布局前保留可恢复的原文件；布局结果仍需重新校验文本框、端口、分组和连线。
- 不因导出文件嵌入了 XML 而删除 `.drawio`。

## 9. 验收清单

### 事实

- [ ] 节点、边界、关系、方向和标签与当前证据一致。
- [ ] 功能职责归属于实际执行或管理该功能的组件，工作目录和能力配置没有被画成运行时管理主体。
- [ ] 设计、假设和证据缺口没有被伪装成已确认现状。
- [ ] 主问题、阅读入口和主链清楚。

### 结构

- [ ] XML 可解析，ID 唯一，边的端点都存在。
- [ ] 容器、子节点和跨容器边的父子关系正确。
- [ ] 独立文本框为 `connectable=0`，且通过 `safeX`、`safeY` 检查。
- [ ] 连线没有连接到文本对象。

### 视觉

- [ ] 全图字体族一致，层级不超过四级，同级样式一致。
- [ ] 分区表头与普通模块按各自规则对齐，没有因批量修改混用对齐方式。
- [ ] 配色以主链强调色和中性色为主；图例用视觉样例直接说明功能语义。
- [ ] 最终显示尺寸没有异常换行、裁切、遮挡、字体替换或过小文字。
- [ ] 节点和容器对齐，间距稳定，空白与内容量匹配。
- [ ] 不选择连线也能追踪起点、路径、方向和终点。
- [ ] 箭头末段、标签、折点和交叉点符合约束。

### 交付

- [ ] `.drawio` 可编辑并保持为事实源。
- [ ] 只生成用户要求、目标文档需要或临时检查需要的导出物。
- [ ] 已按视觉风险选择静态校验、局部预览或整图预览；无视觉变化时没有调用图片查看能力。
- [ ] 只有必要时才打开 Draw.io 图形界面。
